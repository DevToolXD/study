# 책 사진 → 문제 150개 → 앱

- **비용 없음.** 이 스킬은 Claude Code 안에서 돈다. Claude Pro 계정으로 로그인해 쓰면 구독 한도 안에서 실행되고,
  API 키나 API 호출은 필요 없다. 앱도 AI 를 부르지 않는다. 문제는 여기서 미리 만들어 두고,
  무엇을 낼지는 앱이 규칙으로 정한다(많이 틀린 유형은 더 자주, 6번 풀고 맞히면 정복).
- **복사·붙여넣기 없음.** `data/library.json` 을 바꾸고 push 하면 앱이 열릴 때 자동으로 가져간다.

요청: `$ARGUMENTS`

## 1. 입력과 종류

- 형식: `<과목> <시험·단원 이름> <사진 경로...>`. 경로는 파일이거나 폴더다. 경로가 없으면 `inbox/` 의 이미지를 쓴다.
- 과목이나 시험·단원 이름이 빠졌을 때만 짧게 한 번 묻는다.
- **종류(`--kind`)는 과목 이름으로 정한다.** 사용자가 직접 말하면 그대로 따른다.

| kind | 과목 | 만드는 문제 |
|---|---|---|
| `vocab` | 영어·일본어·한자 등 단어 암기 | `word` 만. 사진에 있는 단어를 모두 뽑는다. 앱이 한 단어로 뜻 고르기, 단어 고르기, 직접 쓰기를 순서대로 만든다 |
| `math` | 수학·물리 등 계산 문제 | `short` 60% + `mc` 40%. 같거나 비슷한 유형을 숫자와 상황을 바꿔 여러 개 |
| `quiz` | 사회·역사·과학·국어 등 | `ox` 40% + `mc` 40% + `short` 20% |

- **총 150개가 기본**이다(`--target 150`). 사용자가 개수를 말하면 그 수로 바꾼다.
- 사진 내용이 적어 150개를 채울 수 없으면 억지로 늘리지 않는다. 있는 만큼만 만들고 모자란 이유를 알린다.

## 2. 절차

1. 사진을 하나씩 Read 도구로 연다. 이미지를 직접 읽을 수 있다.
   - HEIC 는 `sips -s format jpeg 입력.heic --out /tmp/p.jpg`(macOS)로 바꾼다. 너무 크면 `sips -Z 1800 입력.jpg --out /tmp/p.jpg`.
   - 흐리거나 잘려서 못 읽는 부분은 건너뛰고 마지막에 알린다.
2. 사진에 **실제로 적힌 내용만** 근거로 쓴다. 추측하거나 책에 없는 지식을 넣지 않는다.
3. **유형(`topic`) 목록을 먼저 정한다.** 같은 방식으로 푸는 문제 묶음이다.
   - 수학: "일차방정식 풀기", "기울기 구하기" 처럼 푸는 방법 단위
   - 사회·역사·과학: 단원이나 개념 이름 ("조선 후기 경제", "광합성")
   - 단어: Day·Unit 번호나 품사
   - 6~15개, 24자 이하. **같은 유형은 모든 배치에서 같은 이름**을 쓴다.
   - 이미 있는 시험이면 `node tools/quiz.mjs list --topics` 로 기존 이름을 먼저 본다.
4. **50개 안팎씩 나눠** 만들고, 배치마다 저장한다. 한 번에 150개를 쓰면 길어서 끊기기 쉽다.

   ```bash
   node tools/quiz.mjs add --subject "수학" --exam "3단원 함수" --kind math --target 150 --source "교과서 p.52-58" <<'JSON'
   [
     {"type":"short","question":"y = 2x + 3 에서 x = 4 일 때 y 의 값은?","answer":"11","topic":"함숫값 구하기","explanation":"2×4+3 = 11"},
     {"type":"mc","question":"y = 3x - 1 의 기울기는?","choices":["3","-1","1/3","-3"],"answer":"3","topic":"기울기","explanation":"x 의 계수가 기울기예요."}
   ]
   JSON
   ```

   출력의 "목표 150개까지 N개 남았어요"가 0이 될 때까지 같은 명령으로 이어서 추가한다. 중복은 스크립트가 걸러낸다.
5. **수학 정답은 직접 계산해서 확인한다.** 숫자만 바꾼 변형은 임시 스크립트(저장소 밖, 예: `/tmp/gen.mjs`)로 문제와 정답을 함께 계산해 JSON 을 만든다.
   손으로 쓴 정답은 틀리기 쉽다. 그림이 있어야 풀 수 있는 문제는 글로 풀어 쓰거나 건너뛴다.
6. `node tools/quiz.mjs validate` 가 "정상"인지 확인한다.
7. 저장하고 올린다. `git branch --show-current` 가 앱이 배포되는 브랜치(`master`)인지 먼저 본다.

   ```bash
   git add data/library.json
   git commit -m "quiz: 수학 3단원 함수 +150"
   git pull --rebase && git push
   ```

   push 가 거절되면 `git pull --rebase` 후 다시 시도한다. `library.json` 이 충돌하면 상대 파일을 받은 뒤 같은 `add` 명령을 다시 실행한다.
8. 한 줄로 알린다: 종류와 개수(유형별), 건너뛴 이유, 못 읽은 부분, 그리고 "Pages 반영까지 1~2분, 그 뒤 앱을 열면 자동으로 들어와요".
9. `inbox/` 에서 가져온 사진은 `inbox/done/` 으로 옮긴다. (`inbox/` 는 git 에 올라가지 않는다.)

Claude Pro 사용량이 모자라면 중간에 멈추고 어디까지 저장했는지 알린다. 저장한 배치는 그대로 앱에 들어가고, 나중에 같은 명령으로 이어서 채울 수 있다.

## 3. 문제 JSON

모든 문제에 `topic`(유형)과 `explanation`(해설 한 문장)을 붙이고, 쪽수를 알면 `page` 도 넣는다.

```json
{ "type": "ox",    "question": "문장", "answer": true }
{ "type": "mc",    "question": "문제", "choices": ["가","나","다","라"], "answer": "정답 보기를 글자 그대로" }
{ "type": "short", "question": "문제", "answer": "12", "alts": ["12cm", "열둘"] }
{ "type": "word",  "term": "abandon", "meaning": "버리다, 포기하다", "pos": "동사", "example": "He abandoned the plan." }
```

- `mc`: 보기는 2~5개이고 서로 달라야 한다. `answer` 는 정답 보기의 글자 그대로 쓴다. 정답 위치를 섞는다. (앱이 풀 때 한 번 더 섞는다.)
- `short`: 정답은 한 줄. 같은 뜻의 다른 표기는 `alts` 에 넣는다. 숫자·분수는 `1/2`, `-3` 처럼 쓴다. 앱이 `x=3` 과 `3`, `12cm` 와 `12`, `1/2` 와 `0.5` 를 같게 본다.
- `word`: `meaning` 은 한국어 뜻. 뜻이 여러 개면 `, ` 로 이어 쓴다. `example` 은 단어가 들어간 짧은 문장(있을 때만).

## 4. 문제 작성 규칙

- 한 문장에 사실 하나. 앞뒤 문맥 없이도 읽히게 쓴다.
- `ox` 는 O 와 X 가 비슷한 비율이 되게 한다. X 문장은 책의 문장에서 숫자·주체·인과·정의 중 하나를 살짝 바꿔 그럴듯하게 만든다. "항상", "절대" 같은 말만 붙여서 틀리게 만들지 않는다.
- `mc` 의 오답 보기는 그럴듯해야 한다. "모두 맞다" 같은 보기는 쓰지 않는다.
- 수학은 **사진의 문제마다 유형 이름을 붙이고, 유형마다 숫자와 상황을 바꾼 문제를 여럿** 만든다. 쉬운 것부터 어려운 것까지 섞고,
  사진에서 자주 나오는 유형일수록 많이 만든다. 해설에는 풀이 한두 줄을 적는다.
- 같은 내용을 표현만 바꿔 반복하지 않는다. 표나 그림은 문장으로 풀어서 묻는다.
- 한국어로 쓴다. 영어 교재면 영어 문장에 한국어 해설을 붙여도 된다.

## 5. 리프레시: 6번 푼 문제가 늘었을 때

앱은 문제를 6번 풀고 마지막에 맞히면 **정복**으로 빼고, 남은 문제가 25% 이하가 되면 "새 문제로 바꿀 때예요"라고 알려 준다.
`/quiz 리프레시 <과목> <시험>` 요청이 오면:

1. `node tools/quiz.mjs list --topics` 로 현재 유형과 개수를 본다.
2. 원본 사진이 있으면 다시 읽는다. (경로를 모르면 `inbox/done/` 를 보고, 없으면 사용자에게 묻는다.) 사진이 없으면 기존 유형 이름을 바탕으로 만든다.
3. 기존 문제와 겹치지 않는 **새 문제 150개**를 같은 시험에 `add` 한다. 중복은 자동으로 빠진다. 사용자가 "약한 유형: ○○" 을 알려 주면 그 유형을 1.5배로 만든다.
4. 수학은 같은 유형에서 숫자와 상황을 바꾼 새 문제로, 단어는 사진에서 아직 안 뽑은 단어로 채운다.
5. 기존 문제는 지우지 않는다. 기기에서 정복한 문제는 앱이 알아서 뺀다.

## 6. 이름과 모양

- 과목 이름은 앱에서 만든 과목과 **공백·대소문자를 무시하고 같은 이름이면 같은 과목**으로 합쳐진다. 시험·단원도 같은 이름이면 앱에서 미리 만든 빈 시험에 채워진다. 앱에 있는 이름 그대로 쓴다.
- 새 과목이면 이름으로 아이콘과 종류를 고르고 색은 자동이다. 바꾸려면 `--icon`(book type calc flask atom leaf globe columns hourglass code music palette pencil bulb ball chart star compass), `--color`(blue green orange pink purple teal), `--kind`(vocab math quiz).

## 7. 다른 명령

```bash
node tools/quiz.mjs list --topics                          # 과목·시험·유형별 개수
node tools/quiz.mjs remove --subject 수학 --exam "3단원"    # 시험 삭제
node tools/quiz.mjs remove --subject 수학 --exam "3단원" --question "기울기"   # 문제 하나 삭제
```
